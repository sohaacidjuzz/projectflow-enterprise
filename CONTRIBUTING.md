# Contributing

1. Create a feature branch from `main`.
2. Keep changes focused and document meaningful architecture changes.
3. Run the frontend build before opening a PR.
4. Run the Docker build for changes affecting deployment.
5. Never commit `.env`, credentials, uploaded files, or `node_modules`.
6. Use clear commit messages such as `feat: add task comments` or `fix: validate upload size`.

Pull requests should explain the problem, the implementation, and how the change was tested.
